## Summary

Expose the built-in provider type separately from the provider-instance identity in the providers API. A named instance such as `copilot-work` now remains the selectable `providerId` while reporting `github-copilot` as its non-secret type.

Refs #4192

Remaining issue scope: Portal create/list/inspect/remove/reassignment workflows; complete foreground/background synthetic routing evidence; concurrent refresh and restart separation; quota, health, usage, discovery-failure and recovery isolation; exported-template requirements; and the complete clean-install synthetic-server fixture.

## Changes

- Project each registered provider instance with a distinct `type` field resolved from its configured provider declaration.
- Preserve canonical compatibility by using the registered provider key as the type when no explicit type exists, and map the `copilot` alias deterministically to `github-copilot`.
- Keep credentials outside the response contract; named instance configuration contributes only its type discriminator.

## Anti-reinvention

The change reuses the existing `IModelFilter` provider-instance enumeration, live platform-configuration options monitor, `ProviderConfig.Type`, and `ProviderInfo` response. Current source, merged #4353/#4514/#4582/#4673 slices, applicable repository instructions, and the bounded open-PR set were checked. No second provider registry, credential projection, or transport abstraction is introduced.
